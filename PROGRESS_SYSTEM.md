# Progress & Motivation System

## Goal
Make learning consistent, visible and enjoyable without turning it into a streak game that rewards rushing.

## Daily session card
Every lesson begins with:
- **Today:** exact topic and outcome
- **Why it matters:** one practical sentence
- **Learn here:** 1 primary link + optional second link
- **Build here:** exact environment (usually Colab, Kaggle or local project) and what file/notebook to create
- **Time choices:** Quick (25–35 min), Standard (60–90 min), Deep (120–180 min)
- **Finish line:** observable evidence needed to complete the lesson

## Keep it interesting
Each day should use at least two of these, rotating them:
- tiny real-world problem
- debugging mystery
- predict-the-output challenge
- build something personally useful
- compare two AI answers/models
- mini quiz
- explain-it-back challenge
- improve yesterday's project
- small game/score challenge
- "break it on purpose" experiment

Do not add entertainment that distracts from mastery.

## Weekly rhythm
Every 7 learning sessions:
1. Short review quiz.
2. One mini-project using several skills.
3. "What can I now do that I couldn't do last week?"
4. Update mastery and weak topics.
5. Adjust the next week if necessary.

## Progress evidence
A completed lesson should leave at least one:
- notebook,
- script,
- quiz/mastery result,
- project commit,
- written explanation,
- debugging solution.

## Progress metrics
Track:
- sessions completed
- current track/day
- mastery by topic (0–4)
- projects completed
- weak topics
- approximate focused minutes
- current learning streak (optional; never punish a broken streak)
- confidence note (learner's own 1–5 rating)

## Completion rule
The AI proposes a STATE update only after evidence of completion. If the AI has GitHub write access and the learner explicitly asks it to update progress, it may update STATE on an appropriate branch. Otherwise provide the exact update or guide the learner.

## Boredom rule
If the learner says the lesson is boring, too slow or too difficult, adapt the *method*, not the learning objective: switch example/project, shorten theory, add a challenge, or review a prerequisite.
